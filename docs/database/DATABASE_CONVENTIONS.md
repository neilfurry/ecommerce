# Database conventions

PostgreSQL 17 with Prisma 7. The schema lives in `prisma/schema.prisma`. Every rule below is
checked in review, and the rules marked **CI** are also checked automatically. Day-to-day commands
are in [../development/LOCAL_DATABASE.md](../development/LOCAL_DATABASE.md). The reasoning is in
ADR [0003](../architecture/adr/0003-database-conventions.md) and
[0004](../architecture/adr/0004-money-and-currency.md).

## Naming

| Object           | Convention                             | Example                                      |
| ---------------- | -------------------------------------- | -------------------------------------------- |
| Prisma model     | PascalCase, singular                   | `StoredFile`                                 |
| Table            | snake_case, plural (`@@map`)           | `stored_files`                               |
| Column           | snake_case (`@map`)                    | `original_name`                              |
| Foreign key      | `<entity>_id`                          | `seller_id`                                  |
| Prisma enum      | PascalCase, `<Entity><Attribute>`      | `FileStatus`                                 |
| PostgreSQL enum  | snake_case (`@@map`)                   | `file_status`                                |
| Enum values      | UPPER_SNAKE_CASE                       | `AVAILABLE`, `PENDING_REVIEW`                |
| Index            | Prisma default `<table>_<columns>_idx` | `stored_files_purpose_status_created_at_idx` |
| Unique           | Prisma default `<table>_<columns>_key` | `stored_files_bucket_object_key_key`         |
| CHECK constraint | `<table>_<column>_check`               | `stored_files_size_bytes_check`              |

## Identifiers

- Business entities: `id String @id @default(uuid(7)) @db.Uuid`. UUIDv7 is time-ordered, so new
  rows append to the end of the primary-key index (better write performance than random UUIDv4)
  and ids are safe to expose in URLs.
- The id is generated by Prisma, not by a database default. Raw SQL inserts must supply it.
- Small reference tables may use a natural key (`currencies.code`).

## Timestamps

- Every table has `created_at` (`@default(now())`) and `updated_at` (`@updatedAt`), both
  `@db.Timestamptz(3)`.
- Values are stored and compared in UTC. Containers run with `TZ=UTC`, and the UI converts to
  `Asia/Manila` for display.
- Soft-deletable records add `deleted_at`, consistent with `status` (see below).

## Status and lifecycle

- A record with a lifecycle has a `status` column of enum type `<Entity>Status`. The enum's first
  value is the initial state.
- Allowed transitions are enforced in the owning service, inside a transaction, never by the
  client. Phase 5 introduces a shared state-machine helper for orders.
- Where a status implies other columns, a `CHECK` constraint enforces it, e.g.
  `stored_files_deleted_at_check: (status = 'DELETED') = (deleted_at IS NOT NULL)`.
- Prefer status values over boolean flags for anything that may gain a third state.

## Enums

- Use a PostgreSQL enum for closed sets that change only with code (statuses, purposes, types).
- Use a reference table for sets that admins configure (currencies, categories, payment methods).
- Adding a value is a migration. Never rename or remove a value that has been used. Deprecate it
  in code instead.
- Document every value with a `///` comment in `schema.prisma`.

## Money

- `Decimal(19, 4)` plus a `currency CHAR(3)` foreign key to `currencies`. Never `Float`.
- Decimal strings in JSON (`"1499.50"`). Arithmetic uses `Prisma.Decimal`.

## Integrity

- Foreign keys for every relationship, with an index on every foreign-key column.
- Unique constraints for natural uniqueness (e.g. `(bucket, object_key)`).
- `CHECK` constraints for value rules Prisma cannot express. They are appended by hand to the
  migration SQL and covered by e2e tests (`database.e2e-spec.ts`).
- Financial records (ledger entries, payments) are append-only. Corrections are new reversing
  rows (Phase 8).
- Orders snapshot product name, SKU, price, quantity, discount and tax at purchase time (Phase 5).
- Multi-row business writes run in `prisma.$transaction`.

## Migrations

- Created with `pnpm db:migrate`, applied with `pnpm db:deploy`, committed together with the schema.
- **CI:** `pnpm db:check` fails the build when the migrations and `schema.prisma` disagree.
- Never edit a migration that has been applied anywhere else. Add a new one.
- Seeds (`prisma/seed.ts`) contain reference data only and use `upsert`. Any demo data is marked
  development-only.
